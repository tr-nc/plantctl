# GL-MT3000 路由器的日常断电

用户提到的型号按 **GL.iNet GL-MT3000 / Beryl AX** 理解。尚未登录或检查这台
路由器，实际固件版本、已安装服务、是否连接 USB 存储，以及它是否就是当前
Orange Pi 所连接的路由器，均未确认。

## 实用建议与适用边界

**原厂固件、普通路由/VPN 用途，没有固件维护或额外存储写入时，日常直接断开
电源通常是可行的操作，不必每次都专门 SSH 关机。** 这是有适用条件的操作建议，
不是厂商对所有固件、插件和断电时机的无故障保证；以前拔电没有出问题，也不能
证明任何时候拔电都安全。

应区分以下场景：

| 场景 | 操作 |
| --- | --- |
| 正常路由，未进行维护或已知存储写入 | 通常可直接断开电源；避免连续快速拔插 |
| 固件升级、刷机、恢复过程 | 不要断电，等待流程完整结束；升级中禁止断电有官方明确警告 [2] |
| 刚保存设置、安装插件 | 等待保存/安装及相关重启完成后再断电；固定等待几秒不代表所有写入都完成 |
| USB 硬盘、U 盘共享、下载、数据库等写入 | 先停止写入服务、安全卸载存储，再断电；不能照搬仅做路由时的建议 |
| 自定义固件或额外持久化服务 | 根据实际系统和服务确认优雅停机方法，不在未知固件上假定某个 SSH 命令必定正确 |

GL-MT3000 支持 USB 网络存储，不能因为它是“路由器”就忽略外接磁盘数据安全。[3]
安全卸载的具体入口需以当前固件界面为准；本次没有验证其位置，也没有给出未经
确认的 `poweroff` / `halt` 硬件行为或断电等待秒数。

官方用户指南说明：连接电源并插入插座后会**自动启动**，不必另外按开机键。[1]
不要把 Reset 恢复/重置操作当作关机；本次没有确认用户固件的按键自定义设置。

## 为什么不能仅按“也是 Linux”一概而论

厂商规格列出 GL-MT3000 为 **512MB DDR4、256MB NAND Flash**，与本项目 Orange Pi
使用 microSD 运行 Debian 的存储安排不同。[4] 但 **NAND 这个名称本身不证明更耐
断电**，不能据此给 PMIC、闪存或整机可靠性排序。

实际风险取决于断电时是否在更新固件、写配置、写数据库或写外接磁盘。未检查
本机文件系统、缓存与后台任务，因此不声称“路由器完全不写盘”或“直接拔电
不会损坏数据”。重要配置应保留私密备份。

## 与 Orange Pi 网关的关系

如果该路由器就是 Orange Pi 的 Wi-Fi 接入点：

- 只断路由器、Orange Pi 仍独立供电时，网页/SSH 会暂时不可达；按当前部署，
  MQTT 使用本机回环地址，Zigbee 经 USB 协调器通信，不需要路由器转发。
- 若切断同一插线板，或 Orange Pi 实际取电于路由器 USB，会一起失电，则应
  **先正常关闭 Orange Pi**，不要把路由器的日常断电建议套到整组设备上。
- 关闭网关主机不会自动关闭 Zigbee 插座；有水泵等负载时先独立确认安全状态。

本次未实际断电测试、未操作路由器或 Orange Pi，也没有确认用户的实际供电接法。
网关独立运行的部署与验证范围见 [网关部署记录](zigbee-host-deployment.md)。
